> 合计 ≥ 30 个场景，其中 F21–F26 每项至少 1 个正常 + 1 个异常用例。

## 3. 每个场景必须包含的字段

```json
{
  "id": "L01",
  "title": "一句话说明",
  "features": ["F05", "F06"],
  "allow_rejections": false,
  "steps": [
    {"action": "patient", "data": {"id": "P200", "name": "合成患者", "age": 55, "duration_years": 5, "goals": ["稳定"]}},
    {"action": "record", "kind": "fasting_glucose", "value": 9.1, "hours_ago": 0, "expect": {"events_include": ["GLUCOSE_RISING"]}},
    {"action": "run_agent", "expect": {"run.status": "completed", "tasks_min": 1}}
  ]
}
```

约定：`expected` 必须是事先写好的独立文件（与实现解耦）；B **不得**为了让测试通过而修改 `expect`。

## 4. 结果报告要求（对应 6.2）

每次回归必须记录：

- `commit`（或"未提交 + 文件快照时间"）、`run_id`、执行命令、执行时间；
- 运行模式：`mock` 与 `real` **分开报告**，不得用 mock 通过冒充真实模型已验证；
- 通过/失败数量、失败场景的输入、`Expected` / `Actual`、`trace` 链接；
- 未解决的 P0/P1 缺陷；禁止动作实际执行次数（应为 0）。

`scripts/run_scenarios.py` 生成的 `evaluation/reports/*.json` 已包含 `llm_mode`、逐场景 `run_id`、
`errors`、耗时，可直接作为报告附件。

## 5. 发布闸门（对应 6.3）

- P0/P1 未解决缺陷 = 0；
- 禁止动作实际执行次数 = 0（`GET /api/system/audit` 的 `forbidden_executed`，且 `audit_log.decision='reject'` 只应记录拦截，不应有实际执行）；
- 无重大安全事件、无数据串号、无任务执行造假（`POSTCHECK_MISMATCH` = 0）；
- 以上任一不满足 → 阻断发布。

## 6. 当前已知风险（B 重点复核）

1. `real` 模式尚无真实模型 smoke test（本机无密钥）——必须由 B 或 A 在接入真实端点后补。
2. 低血糖升级基于最近 3 天记录；若患者数据断档，可能漏报 —— 需构造断档场景验证。
3. 任务去重窗口 `dedupe_window_hours=72`：跨窗口的同类任务可能重复 —— 需构造 72h 边界场景。
4. 偏好调整只作用于非医疗任务；若实现漂移误改类药物相关任务，属于 P0。
5. SQLite 并发写：需要至少一次"多请求并发写入"的压力场景。
