# 视频演示操作手册（video_runbook）

> 给 C 角色直接操作。数据已由 B 导入独立库，C 无需研究数据结构。

## 前置环境

1. 后端 API 地址：`http://127.0.0.1:8000/api`
2. 数据库：`.tmp/diabetes_agent_video_demo.db`（B 已导入，勿用默认库）
3. 正式录制前：停 Mock 后端 → 保留同一数据库 → 以 Real 模式重启 → 核对 `/api/system/mode` 为 `real`
4. 真实 API Key 只放本地环境变量，不写入任何文件。

## 六段录制流程

### 第一段：多患者监管总览

- 打开工作台患者总览，展示 12 个患者的多种健康状态、事件数、任务数、人工复核事项。
- 讲解：这是面向医护健康管理人员的工作台，不是患者问答网站。

### 第二段：多事件综合管理（VDEMO-102）

1. 打开 VDEMO-102 历史记录：血糖 7.1→9.3、步数 1500、漏服 2 次；
2. 展示三类事件：`GLUCOSE_RISING`、`MEDICATION_NONADHERENCE`、`LOW_ACTIVITY`；
3. 触发 Agent，展示综合判断、任务创建、优先级与选择依据；
4. 展示真实 `run_id` 与工具轨迹。

### 第三段：主动询问与不确定性（VDEMO-103）

1. 打开 VDEMO-103，展示无服药记录；
2. 触发 Agent，展示主动提出 waiting 问题；
3. 模拟患者回答「记不清」；
4. 展示不确定信息被保留，未生成虚假服药记录。

### 第四段：风险识别与人工复核（VDEMO-104 / VDEMO-105）

1. VDEMO-104（血糖 3.5 + 心慌出汗手抖）→ `HYPOGLYCEMIA_RECORD`；
2. 或 VDEMO-105（血糖 17.2）→ `HYPERGLYCEMIA_RECORD`；
3. 展示 Agent 安全升级、`HUMAN_REVIEW`、人工复核事项、审计轨迹；
4. 不展示任何虚构医疗诊断或治疗建议。

### 第五段：个性化任务与动态调整（VDEMO-108）

1. 打开 VDEMO-108，展示约束「19:00 后照顾家人」与 `LOW_ACTIVITY`；
2. 触发 Agent 创建活动记录任务；
3. 操作人员输入「我19:00以后要照顾家人，改成08:00记录步数」；
4. 展示任务版本更新、时间偏好保存。

### 第六段：任务执行与复评闭环（VDEMO-106 / VDEMO-107）

1. VDEMO-106：完成任务 → 触发正式复评 → 核对进入 `CLOSED`；
2. VDEMO-107：不完成任务 → 演示时钟推进 72 小时 → 自动调度 → 核对 `MISSING_DATA`；
3. 展示最终执行记录与补录需求。

## 特殊患者备用镜头（可选）

- VEDGE-201：档案缺项；
- VEDGE-202：重复/异常导入去重与拒绝；
- VEDGE-203：低阈值边界（3.91 不误判）；
- VEDGE-204：高阈值边界（16.69 不误判）。

## 注意事项

- 所有画面须标注「患者数据为合成虚构数据，系统不是临床诊疗软件」；
- 超时后先查询已有运行结果，勿连续重复点击；
- 真实模型运行、工具执行、数据库结果必须对应同一 `run_id`。
