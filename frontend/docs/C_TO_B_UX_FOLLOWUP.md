B 的结论成立：自动化通过不足以证明用户能找到提问、回复和下一步。此前界面把实现真实性说明重复写成提示，削弱了实际业务内容。

| B 的问题 | 本次实现 | B 应复验的行为 |
| --- | --- | --- |
| P1：等待回答时没有明显入口 | 运行结果、运行详情顶部和运行列表提供“去回答”；查询真实问题状态并按患者、运行或实际返回的 question_id 关联 | 操作后无需展开抽屉即可看见提问和入口；点击一次到对应问题，答复框获得焦点 |


人工重点检查：

1. 发起缺信息核实请求，先不打开运行详情：能否直接看见 Agent 在问什么和“去回答”？
2. 点击“去回答”：患者、问题是否正确，答复框是否定位并聚焦？回答“记不清”后，能否看见实际答复和后续沟通？
3. 打开一条有实际回复的运行：顶部是否直接显示回复与下一步，而不是一排工具统计？
4. 默认层能否解释发生了什么、哪些成功/失败、下一步谁做什么？不以日志或编号辅助解释。
5. 查看日志并复制/下载，核对完整 ID、参数、结果、拒绝码和原始 API JSON。日志的打开/关闭/下载不应产生业务 POST。
6. 对真实失败或核对失败，确认精简提示后仍明显为“部分处理未完成”；不能因成功读取资料而显示整体完成。
7. 三种桌面尺寸检查卡片、气泡、待回答按钮、抽屉及日志。保留真实使用者原话和截图。
