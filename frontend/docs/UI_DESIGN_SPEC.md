# 工作台设计与交互规范

2026-11-05。对象是医护健康管理工作人员；采用浅色、低动效、较高信息密度的健康科技监管界面，沿用Ant Design单一组件体系，不引入商业后台模板。

## 信息架构

216px深色侧栏、顶部状态和患者选择、常驻合成/非医疗器械提示、内容主区。八个一级模块，通知和知识有独立二级入口。监管首页先多患者指标/待办，再重点患者和运行活动；患者档案用标签组织记录、事件、任务、问题、快照，避免所有内容堆一页。

记忆点是“每次行动有据可查”的执行链与业务化决策详情：真实阶段芯片、工具动作、关联对象、证据、自检。无装饰动画、假思考流或虚构临床目标线。

## 交互真实性

- 请求和响应均经统一Adapter/Zod；加载、错误、空数据分别显示。部分患者加载失败时统计只代表已加载范围。
- 记录表单按八类切换字段，自动整理payload；切换不残留数值。导入显示真实坏行和重复结果。
- 请求等待中锁定写入和患者选择，不自动重试；超时提示可能已保存，先重新查询。患者切换的首帧隐藏旧患者数据。
- 轨迹只显示实际返回阶段，完整JSON折叠保留。失败状态、后端拒绝与不确定性显式显示；不因工具读取ok而宣称所需业务完成。
- 人工完成/改期、模拟答复/偏好、规则触发、Mock规划、Real原生工具来源有不同文案。mode=real但缺原生响应元数据时注明不能核验来源。
- 知识图表只连接真实观测，不插值、不画临床目标线。独立搜索与run证据分开。

## 响应式与可访问性

1920×1080、1440×900、1366×768在真实Chrome逐页检查无文档横向溢出。表格保留内部横向滚动，窄屏堆叠双列，抽屉最大宽100vw。基础键盘焦点可见，表单有标签，装饰导航图标不参与可访问名称。

reduce模式采用0.01ms动画/过渡，而非取消组件结束事件；已通过实际患者下拉选择测试。机械检查中的横向营销导航高度规则不适用于用户指定的纵向医护侧栏；不通过伪造数据标记把纵向菜单宣称为80px单行导航。截图及浏览器无溢出结果作为该布局验收依据。

已知：仍有现有组件弃用提示及部分打包块>500KB。没有加入新的UI框架或云字体依赖；没有完成生产负载/低性能终端评测。

实际营销布局机械脚本结果6/7，唯一FAIL为R5：纵向侧栏高426px、非单行。用户明确要求左侧导航，因此该横向营销规则不适用，不伪造通过。其余规则通过；完整输出本机保留。AI-tell文本检查CLEAN。
